# Plan de migration des librairies JavaScript vendorisées

> Document de suivi. Cocher chaque tâche à la complétion. Aucune de ces
> librairies n'est gérée par un gestionnaire de paquets front-end (pas de
> `package.json` de dépendances runtime) : tout est copié en dur sous
> `administrator/components/com_breezingformsng/libraries/` et
> `components/com_breezingformsng/libraries/`.

## Méthode

Pour chaque librairie : vérifier s'il existe une version amont plus récente
et compatible en drop-in (même API, même mode de chargement `<script>`
classique — le projet n'a pas de pipeline de build JS), avant de choisir
entre bump de version et remplacement complet.

## Ordre de traitement recommandé

1. ✅ **Nettoyage mort (aujourd'hui)** : suppression des binaires Flash/Silverlight inertes de Plupload (`Moxie.swf`, `Moxie.xap`) — zéro risque, zéro changement de comportement observable (Flash Player n'existe plus nulle part).
2. ✅ **overLIB → tooltip Bootstrap natif (aujourd'hui)** — `RenderingEngine.php` (élément "Tooltip") migré vers `HTMLHelper::_('bootstrap.tooltip', '.hasTooltip')`, même pattern déjà utilisé par les renderers QuickMode sur le frontend. `overlib_mini.js` supprimé (fichier + entrée `joomla.asset.json` orpheline).
3. ✅ **wz_dragdrop supprimé (aujourd'hui)** — audit du dépôt : zéro appel à son API n'importe où dans le code. Le chargement conditionnel en mode preview (`RenderingEngine.php`), l'entrée `joomla.asset.json` orpheline et le dossier vendorisé (`wz_dragdrop.js`, `transparentpixel.gif`) ont été retirés. Pas de remplacement — il n'y avait rien à remplacer.
4. ✅ **SweetAlert v1 → SweetAlert2 (aujourd'hui)** — `sweetalert.min.js` (v1) remplacé par `sweetalert2.min.js` (v11.26.25, bundle officiel `sweetalert2.all.min.js`) ; les 3 `RuntimeAssetLoader::script()` (ClassicRenderer, OnePageRenderer, BootstrapRenderer) repointés. Le seul appel réel trouvé dans tout le dépôt (`swal(error)` dans le piece `gn_validate_page_fin` du stdlib package importable) modernisé en `Swal.fire(error)` ; reste compatible même sans cette modernisation grâce à l'alias `window.swal` que SweetAlert2 fournit lui-même.
5. ✅ **Ladda supprimée (2026-10-13)** — remplacée par l'indicateur de chargement de Bootstrap 5 (`quickmode-submit-spinner.js`) ; les quatre fichiers de `libraries/jquery/ladda/` et l'attribut `data-style` du bouton sont retirés. Les scripts du thème appellent `bfSubmitSpinner.stop()` à la place de `ladda_button.ladda("stop")`, et `bf_restore_submitbutton()` relie le bouton restauré avec `bfSubmitSpinner.bind()`.
6. ✅ **jTable supprimé (aujourd'hui)** — comme wz_dragdrop et SweetAlert v1, audit confirmant zéro appel `.jtable(...)` first-party : la migration vers `searchtools` natif avait déjà eu lieu, jTable n'était plus que du poids mort (464 Ko : lib, 21 fichiers de localisation, thème "metro"). Asset `com_breezingformsng.jtable`/`.jtable-style`/`.jq-ui-css` retirés de `joomla.asset.json`, classe `jtable-main-container` retirée des templates Pieces/Scripts, ~250 lignes de CSS mort nettoyées dans `admin.css`/`custom.css` (en préservant les règles `.table` qui étaient mélangées dans des sélecteurs combinés `.table, .jtable`).
7. ✅ **jQuery UI → Bootstrap 5 (aujourd'hui)** — `#menutab` (constructeur de formulaire QuickMode) migré vers `nav-tabs`/`tab-content`. `jq-ui.min.js` (2 copies) et le thème "easymode" orphelin (60 fichiers) supprimés. `useScript('bootstrap.tab')` ajouté (Joomla 6 ne le charge pas par défaut, contrairement à `.modal`/`.popover`/`.collapse`). CSS `.ui-tabs-*` retargeté vers les classes Bootstrap dans `admin.css`/`custom.css`, en préservant les icônes/couleurs déjà en place. **Vérifié en navigateur réel** avec connexion admin : bascule d'onglet fonctionnelle, confirmée par l'état DOM avant/après clic.
8. ✅ **jquery.validationEngine supprimé (aujourd'hui)** — en creusant l'implémentation avant de concevoir un remplacement, découverte que le "système de bulles d'erreur par champ" n'a **jamais fonctionné** : les 2 appels utilisent `.bfvalidationEngine(...)`, une méthode que le plugin vendorisé n'expose pas (il expose `$.fn.validationEngine`, sans préfixe), doublement gardée par une vérification sur une propriété jamais définie. Code mort depuis probablement un renommage "bf" incomplet, jamais l'affichage réel des erreurs (qui passe par le bandeau `bfShowDefaultErrors`, intact). Suppression de la lib (JS + CSS, copies admin et site) et des 5 gardes morts associés (`quickmode-error-alerts.js`, `quickmode-error-alerts-bootstrap.js`, `quickmode-post-init.js`, `quickmode-post-init-onepage.js`, `quickmode-post-init-mobile.js`) — pas de conception d'UX nécessaire, il n'y avait rien à remplacer.
9. ✅ **jQuery Mobile → Bootstrap 5 (fait en parallèle, fusionné séparément)** — réécriture complète de `MobileRenderer.php` (1595 lignes, 21 points de retouche : structure page/header/content, accordéon, boutons, groupes de champs, grilles) et de `quickmode-post-init-mobile.js` (passage de `pageinit`/`mobileinit` à `DOMContentLoaded`, retrait des appels `.checkboxradio()`/`.textinput()`/`.selectmenu()` propres à jQuery Mobile). Les 4 CSS et le JS vendorisés supprimés. **Vérifié en navigateur réel** une fois le conteneur de dev réparé (cf. souci ContentBuilderNG, sans rapport, résolu séparément) : rendu mobile déclenché avec un vrai user-agent mobile, structure `bfMobilePage`/`bfMobileHeader`/`bfMobileContent` correcte, persistance de la session mobile après rechargement, et surtout — test d'interaction réel sur l'accordéon de section : clic sur le bouton `data-bs-toggle="collapse"` fait bien passer la classe de `collapse show` à `collapse`, confirmant que les ids générés (`{section}-collapse`) correspondent correctement entre le déclencheur et la cible. Zéro erreur console liée à jQuery Mobile.
10. ✅ **qTip2 supprimé (aujourd'hui)** — audit du seul chemin d'appel réel (`ClassicRenderer.php`, infobulle de champ hors `joomlaHint`) : remplacé par le tooltip Bootstrap natif déjà utilisé partout ailleurs dans le composant, avec `HTMLHelper::_('bootstrap.tooltip', '.hasTooltip')` déplacé en tête de `render()` (un seul enregistrement du comportement au lieu d'un appel par champ). `MobileRenderer.php` chargeait la lib sans jamais l'utiliser (son propre mécanisme d'infobulle, en bouton `.tooltip`, n'a rien à voir avec qTip2) — chargement mort retiré. Les 3 copies vendorisées (`tooltip.js` site+admin, `tooltip.css` site) supprimées. Page "About" admin nettoyée par la même occasion : entrées jQuery UI/ValidationEngine déjà orphelines (oubli de PR #52) retirées de l'inventaire des libs, ainsi que le pattern de regex mort associé à ValidationEngine dans l'extracteur de version.
11. ✅ **Plugin jQuery MD5 supprimé (aujourd'hui)** — audit du dépôt entier : aucun appel (`.md5(...)`, `jQuery.md5`, etc.) nulle part dans le code first-party, uniquement chargé au constructeur QuickMode admin (`QuickmodeHtml.php`, `HtmlView.php` via l'asset `com_breezingformsng.md5`) sans jamais être utilisé — code mort pur, même schéma que wz_dragdrop/jTable. Entrée `joomla.asset.json`, dépendance dans `quickmode-app`, les 2 `useScript()` et le fichier vendorisé retirés.
12. ✅ **Plugin jquery-json supprimé (aujourd'hui)** — contrairement à MD5, usage réel confirmé : 22 appels `JQuery.toJSON(...)` sérialisant l'attribut `mdata` du constructeur QuickMode admin (`quickmode-app.js`, `quickmode-elements.js`, `tmpl/quickmode/default.php`). Tous repointés vers `JSON.stringify()` natif — remplacement direct, tous les appels sérialisant des littéraux objet simples sans `Date`. Entrée `joomla.asset.json`, dépendance dans `quickmode-app`, les 2 `useScript()` et le fichier vendorisé retirés.

## Notes de vérification

- Vérifications faites via le registre npm et les tags GitHub officiels (Remodal, pickadate, Plupload, Ladda) le 2026-07-24.
- Plupload : le fichier vendorisé `plupload.js` est byte-for-byte identique au source du tag GitHub `v3.1.5` malgré l'en-tête `v3.1.2` — aucune évolution fonctionnelle entre ces tags.
- Pour les librairies marquées "aucune action possible", revérifier périodiquement (une fois par an) au cas où le projet reprendrait vie ou qu'un fork actif apparaîtrait.
