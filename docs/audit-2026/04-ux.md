# Audit UX/UI et accessibilité — BreezingForms NG (2026)

Audit en lecture seule. Aucun code applicatif, aucune donnée ni aucun état Git n'a été modifié ; ce fichier est le seul livrable.

## 1. Méthode, écrans observés et non observés

**Référentiels** : `docs/charte-graphique-breezingformsng.md` (Atum, jetons `--bfng-*`, zéro `!important`, zéro couleur en dur hors jetons, `data-bs-theme` respecté), WCAG 2.2 AA, Joomla 6 / Bootstrap 5.3.

**Outils** : lecture du code (tmpl, `QuickmodeHtml.php`, JS admin et site, CSS), consultation HTTP de l'instance `http://localhost:9080` (HTML rendu), captures avec Chrome headless (`--screenshot`, bureau 1280 px et mobile 390 px). Le skill `frontend-design` n'a pas été chargé : l'audit porte sur la conformité à la charte existante, pas sur une direction visuelle nouvelle.

**Limite majeure** : aucun identifiant administrateur n'est disponible pour cette session. Tout le back-office est donc **déduit du code**, aucun écran admin n'a été observé dans un navigateur. Les captures ci-dessous concernent uniquement le front public.

| Écran | Statut |
|---|---|
| Front : formulaire d'exemple `/tests/bf-sample-contact.html` (thème « carte », Bootstrap) | **Observé** (HTML + captures bureau et mobile ; sans soumission) |
| Front : `/tests/bf-sample-widgets.html`, `/contact/bf-contactez-le-vcmb.html` | HTML récupéré (rendu 200, pas de « not found »), non capturé |
| Front : `/gilles/bf-formulaire-debug.html` | **Observé** : affiche `[Form Gilles_Debug not found!]` (formulaire absent de l'instance, constat de données de test, pas de défaut du composant) |
| Front : états d'erreur de validation, page « Message envoyé », captcha en erreur, reCAPTCHA, signature, calendrier, upload | **Déduit du code** (aucune soumission effectuée pour ne pas créer de données) |
| Admin : liste des formulaires, scripts, pièces, menus, enregistrements, paquets, intégrateur, À propos, audit | **Déduit du code** |
| Admin : éditeur Quick Mode (arbre jstree, onglets, propriétés, menu de types) | **Déduit du code** |
| Admin : configuration (`config.xml`), mode sombre, responsive admin | **Déduit du code** |

Toute affirmation sur le rendu admin (mise en page, sombre, mobile) est donc une hypothèse à confirmer. Le niveau de confiance est indiqué pour chaque constat.

## 2. Parcours débutant (création d'un premier formulaire)

Évalué sur le code uniquement.

1. **Liste des formulaires** (`tmpl/forms/default.php`) : conforme au patron Joomla natif (searchtools, `grid.checkall`, tri, pagination, jeton CSRF). Point d'entrée vers l'éditeur par le titre, avec `title` d'aide. Bon point de départ.
2. **Création** : une nouvelle fiche ouvre Quick Mode avec un nœud racine par défaut (`tmpl/quickmode/default.php`) dont `submitLabel: "submit"`, `cancelLabel: "reset"`, `pagingNextLabel: "next"` sont des valeurs anglaises en dur, non traduites (voir UX-007).
3. **Ajout de contenu** : trois boutons « + » (page, section, élément) à icône seule, avec `title` mais sans `aria-label` ni texte visible ; un débutant doit survoler pour comprendre. Le menu « Choisir un type de champ » avec icônes et regroupements par famille est un vrai plus pédagogique.
4. **Arbre** : manipulation principalement par glisser-déposer et menu contextuel (clic droit) ; les entrées « Copier/Coller/Supprimer » sont en anglais (UX-004, UX-007). Un débutant clavier ou tactile n'a pas d'équivalent évident.
5. **Aperçu** : boutons « Aperçu » présents (modales), bon.
6. **Enregistrement** : badge « modifications non enregistrées » (`bfUnsavedBadge`) et scripts de dirty-check : bon retour d'état. Les erreurs de saisie sont en `alert()` natifs bloquants (UX-008).

Conclusion du parcours : structure claire et fonctionnalités riches, mais l'accès au clavier, la traduction de l'éditeur et les messages d'erreur modaux freinent un débutant ou un utilisateur d'aides techniques.

## 3. Constats

### UX-001 — Les champs obligatoires ne sont signalés que par une icône sans équivalent textuel ni attribut `required`
- **Catégorie** : accessibilité front (WCAG 1.3.1, 3.3.2, 4.1.2)
- **Impact** : élevé
- **Confiance** : observé (HTML rendu)
- **Preuves** : sur `/tests/bf-sample-contact.html`, `<label …>Last name <i class="fa-solid fa-asterisk"></i></label>` ; l'`<input id="ff_elem7415">` ne porte ni `required` ni `aria-required` (comptage dans la page : `aria-required` 0, `required` 0). Source : `components/com_breezingformsng/src/Service/Rendering/QuickMode/QuickModeBootstrapClassMapBuilder.php:45` (`icon-asterisk` vers `fa-solid fa-asterisk`) ; style `media/com_breezingformsng/css/theme-carte.css:172-177` (astérisque à 0,6 em, en exposant).
- **Conséquences** : un lecteur d'écran n'annonce pas le caractère obligatoire. L'astérisque, très petit et teinté, est difficile à percevoir. Aucune légende ne définit son sens. Le test est ensuite fait uniquement au clic sur « Envoyer ».
- **Recommandation** : ajouter `aria-required="true"` (sans `required` natif si la validation maison doit rester maître) sur les champs obligatoires, un texte `visually-hidden` « obligatoire » dans le label, l'astérisque en `aria-hidden="true"`, et une légende « * champ obligatoire » en tête de formulaire.
- **Effort** : S
- **Risque de régression** : faible (attributs ajoutés ; vérifier les scripts qui lisent le contenu du label)
- **Tests nécessaires** : test de rendu des attributs ; test Playwright e2e sur le formulaire d'exemple ; vérification avec NVDA ou Orca.

### UX-002 — Contraste non textuel insuffisant des champs du thème « carte »
- **Catégorie** : accessibilité visuelle (WCAG 1.4.11)
- **Impact** : moyen
- **Confiance** : observé (capture) ; ratio calculé
- **Preuves** : `theme-carte.css:181-190` (`background-color: var(--bf-field)` = `#f3f2f2`, `border: 1px solid transparent`) sur une carte `#fff` (`--bf-card`). Le fond du champ contre la carte donne environ 1,1:1. La capture bureau confirme des champs sans contour. La bordure `--bf-line` (`#d9d6d1`) n'apparaît qu'au survol.
- **Conséquences** : la limite d'un champ n'est pas perceptible pour les personnes malvoyantes (seuil 3:1). Le focus est bien traité (contour 2 px `--bf-accent`).
- **Recommandation** : bordure permanente d'au moins 3:1 contre le fond adjacent (par exemple une teinte plus sombre que `--bf-line`), ou fond de champ plus contrasté. Vérifier aussi le mode sombre (`#262d36` sur `#1d232b`).
- **Effort** : S
- **Risque de régression** : moyen (change l'apparence d'un thème livré ; les sites qui le personnalisent seront touchés)
- **Tests nécessaires** : contrôle de contraste automatisé sur les deux thèmes ; capture avant/après.

### UX-003 — Captcha image sans alternative et bouton de rafraîchissement sans nom accessible
- **Catégorie** : accessibilité front (WCAG 1.1.1, 4.1.2, 3.3.8 Authentification accessible)
- **Impact** : élevé pour les utilisateurs aveugles ; la seule voie visible est le captcha image
- **Confiance** : observé (HTML)
- **Preuves** : `<img alt="" … id="ff_capimgValue" …>` ; `<button type="button" …><i class="fa-solid fa-arrows-rotate"></i></button>` sans texte, `title` ni `aria-label` ; image à largeur fixe `230px !important` en ligne. Source : `components/com_breezingformsng/src/Service/Rendering/CaptchaSupportBuilder.php`, `ScriptingEngine.php:593`. Le HTML observé ne propose pas d'alternative audio ni de question textuelle.
- **Conséquences** : l'utilisateur de lecteur d'écran ne peut pas résoudre le captcha. Le bouton est annoncé « bouton » sans indication. La largeur fixe force un défilement horizontal sur écran très étroit (non observé sous 390 px).
- **Recommandation** : donner un `aria-label` explicite au bouton (« Nouveau code »), un `alt` descriptif de l'image avec instructions, et proposer une alternative (reCAPTCHA/hCaptcha/Turnstile déjà gérés par le composant, ou captcha textuel de type question). Remplacer la largeur imposée par `max-width: 100%`.
- **Effort** : M
- **Risque de régression** : faible pour le nom accessible, moyen pour une alternative de captcha
- **Tests nécessaires** : audit axe sur le formulaire d'exemple ; test manuel au lecteur d'écran.

### UX-004 — Arbre Quick Mode : réorganisation uniquement à la souris, menu contextuel en anglais
- **Catégorie** : accessibilité et ergonomie admin
- **Impact** : élevé pour clavier et tactile
- **Confiance** : déduit du code
- **Preuves** : `media/com_breezingformsng/js/admin/quickmode-app.js:407-435` (jstree avec `plugins: ['types', 'dnd', 'contextmenu']`) ; menu `quickmode-app.js:438-465` avec `label: 'Copy'`, `'Paste'`, `'Delete'` en dur ; aucune occurrence de `role=`/`aria-` dans `quickmode-app.js`, `quickmode-tree-model.js` ni `quickmode-elements.js` (seuls `quickmode-type-menu.js` et `quickmode-yesno-switch.js` en contiennent). Aucune commande « Monter/Descendre/Déplacer vers » hors glisser-déposer.
- **Conséquences** : déplacer un champ d'une page à une autre est impossible sans pointeur précis (WCAG 2.1.1 et 2.5.7 Mouvements de glissement). La suppression se fait sans confirmation (à vérifier sur écran). Les libellés ne suivent pas la langue de l'interface.
- **Recommandation** : ajouter des boutons « Monter », « Descendre » et « Déplacer vers » dans le panneau de l'élément sélectionné ; traduire les libellés via `BFQMConfig.labels`, comme le reste ; demander confirmation pour la suppression, ou proposer « Annuler ».
- **Effort** : M
- **Risque de régression** : moyen (modèle d'arbre central)
- **Tests nécessaires** : tests e2e au clavier ; tests du `treeModel.canContain` pour les déplacements ; vérification du dirty-check.

### UX-005 — Sélecteur de langue de l'éditeur construit avec des `<div onclick>`
- **Catégorie** : accessibilité clavier
- **Impact** : moyen
- **Confiance** : déduit du code
- **Preuves** : `administrator/components/com_breezingformsng/src/Helper/QuickmodeHtml.php:335` et `:343` (`<div onclick="location.href = …" class="bfLanguageButton bfng-seg__opt …">`). Absence de `tabindex`, de rôle et d'état courant (`aria-current`/`aria-pressed`).
- **Conséquences** : non atteignable au clavier, non annoncé comme contrôle, état actif uniquement par la classe CSS. Aucun lien réel (pas de clic milieu, pas de copie d'URL).
- **Recommandation** : remplacer par des `<a class="bfng-seg__opt" href="…" aria-current="true">` ou des `<button>`.
- **Effort** : S
- **Risque de régression** : faible
- **Tests nécessaires** : test e2e de changement de langue ; navigation au clavier.

### UX-006 — Boutons d'icône sans nom accessible dans l'éditeur et les listes
- **Catégorie** : accessibilité admin (WCAG 4.1.2, 2.5.3)
- **Impact** : moyen
- **Confiance** : déduit du code
- **Preuves** : `QuickmodeHtml.php:285-303` (boutons `+`, engrenage : icône `aria-hidden`, nom uniquement via `title`) ; `tmpl/forms/default.php:72-80` (bascule de publication : lien `href="#"` + `onclick` + `title`, sans texte masqué, alors que l'état « corbeille » en a un). Les autres listes (`scripts/default.php`) ont, elles, un `<caption class="visually-hidden">`, mais pas la liste des formulaires.
- **Conséquences** : le `title` est un nom de repli peu fiable (non exposé au toucher, parfois non annoncé). Les boutons ne sont pas distinguables par la voix.
- **Recommandation** : ajouter `aria-label` ou un `<span class="visually-hidden">` ; pour la bascule, utiliser un `<button>` ou le composant `data-item-task` de Joomla (déjà présent) ; ajouter un `<caption>` masqué à la liste des formulaires.
- **Effort** : S
- **Risque de régression** : faible
- **Tests nécessaires** : tests de rendu ; axe sur l'éditeur.

### UX-007 — Chaînes visibles non traduites ou en dur
- **Catégorie** : cohérence / i18n (AGENTS.md : « route user-facing strings through translation keys »)
- **Impact** : moyen
- **Confiance** : déduit du code ; observé pour le compteur de caractères
- **Preuves** : (a) `quickmode-app.js:439,448,457` (`Copy`, `Paste`, `Delete`) ; (b) `quickmode-elements.js:25,90,153,…` (`label: 'untitled element'` 18 fois) ; (c) `tmpl/quickmode/default.php:35-47` (valeurs par défaut `"submit"`, `"reset"`, `"next"`, `"back"`) ; (d) clé `COM_BREEZINGFORMSNG_CHARS_LEFT` valant `"chars left"` en `es-ES`, `hu-HU` et `tr-TR` côté site (`components/…/language/*/com_breezingformsng.ini`) et en `hu-HU` côté admin, donc non traduite pour ces langues ; (e) sur la page d'exemple le résumé d'erreurs et le compteur sont rendus dans la langue du site (français) alors que le formulaire est en anglais, ce qui est un artefact des données de test, pas du composant.
- **Conséquences** : interface mélangée, valeurs par défaut anglaises dans des formulaires créés par des utilisateurs non anglophones.
- **Recommandation** : passer (a) à (c) par `BFQMConfig.labels` / `Text::_`, et traduire (d) dans les trois langues manquantes, avec les huit langues mises à jour ensemble (règle du projet).
- **Effort** : S
- **Risque de régression** : faible (les valeurs par défaut de (c) sont stockées dans les formulaires : ne modifier que pour les nouveaux)
- **Tests nécessaires** : test de parité des clés entre langues ; vérification d'un nouveau formulaire en `fr-FR`.

### UX-008 — Erreurs de l'éditeur via `alert()` natifs
- **Catégorie** : messages d'erreur / ergonomie
- **Impact** : moyen
- **Confiance** : déduit du code
- **Preuves** : `quickmode-app.js:599-656` (au moins neuf `alert(BFQMConfig.labels[…])`), `quickmode-tree-model.js:442`.
- **Conséquences** : boîtes bloquantes sans lien avec le champ en erreur, hors du style Joomla, sans focalisation du champ concerné, sans possibilité de lister plusieurs erreurs. Le front dispose déjà d'un bon modèle (voir « Points forts »).
- **Recommandation** : remplacer par des messages en ligne (`invalid-feedback`, `aria-describedby`, `aria-live`) ou par `Joomla.renderMessages`, et déplacer le focus sur le premier champ fautif.
- **Effort** : M
- **Risque de régression** : moyen (flux de validation de l'enregistrement)
- **Tests nécessaires** : e2e des cas titre/nom manquant et nom en double.

### UX-009 — L'éditeur charge une feuille héritée qui contredit la charte et neutralise le focus
- **Catégorie** : cohérence visuelle Atum, mode sombre, accessibilité
- **Impact** : moyen à élevé (à confirmer en navigateur)
- **Confiance** : déduit du code
- **Preuves** : `QuickmodeHtml.php:194` et `View/Quickmode/HtmlView.php:177` chargent `custom.css` ; ce fichier contient 327 `!important` (`grep -c`), `body { background-color: #EEEEEE !important; }` (l. 17), `main input:focus … { outline: 0 none !important; border-color: #3f51b5 !important; background: #f8f8f8 !important }` (l. 59-67), et aucune occurrence de `data-bs-theme`. Le sélecteur `main …` s'applique à tout le contenu `<main>` de la page chargée, pas seulement à l'éditeur. La charte exige zéro `!important` et zéro couleur en dur.
- **Conséquences** : en thème sombre Atum, fond forcé `#EEEEEE` et champs `#f8f8f8` (hypothèse : contraste cassé) ; indicateur de focus remplacé par un changement de bordure/fond de 1 px, au contraste faible (WCAG 2.4.7/2.4.13) ; conflit avec les jetons `bfng-*` qui sont, eux, conformes (`bfng-tokens.css` : 0 `!important`).
- **Recommandation** : retirer progressivement `custom.css` de l'éditeur au profit de `bfng-admin.css`/`bfng-widgets.css` ; en attendant, borner les règles à `#bfQuickModeWrapper` et remplacer le `outline: 0` par un anneau `var(--bfng-focus-ring)`.
- **Effort** : L
- **Risque de régression** : élevé (3 000 lignes de CSS historiques ; l'onglet Options est déjà exempté par `:not(#bfOptionsFieldsWrap *)`)
- **Tests nécessaires** : captures comparatives clair/sombre/mobile de l'éditeur ; test de non-régression visuelle de l'onglet Options.

### UX-010 — Barre d'outils de l'éditeur en flottant avec icônes PNG héritées
- **Catégorie** : cohérence Atum
- **Impact** : faible à moyen
- **Confiance** : déduit du code
- **Preuves** : `QuickmodeHtml.php:243` (`<div style="float:left; margin-right: 3px;">`) autour de `ToolbarHelper::custom('preview', 'publish.png', 'save_f2.png', …)` ; la charte déclare bannir les flottants et les icônes PNG. Le formulaire `adminForm` est imbriqué dans ce conteneur.
- **Conséquences** : boutons d'aperçu/fermeture hors de la barre d'outils Joomla standard, style inline, icônes non adaptées au sombre.
- **Recommandation** : enregistrer les boutons via la barre d'outils Joomla du `HtmlView` (icônes `icon-*`) et supprimer le `float` inline.
- **Effort** : M
- **Risque de régression** : moyen (tâches `preview`, `close`)
- **Tests nécessaires** : e2e Apply/Preview/Close ; capture mobile.

### UX-011 — Les infobulles d'aide ne sont ni focalisables ni tactiles
- **Catégorie** : accessibilité front (WCAG 1.4.13, 2.1.1)
- **Impact** : moyen
- **Confiance** : observé (HTML) et déduit (JS)
- **Preuves** : `<span class="hasTooltip" title="We only use it to reply to you…"><i class="fa-solid fa-circle-question">&nbsp;</i> Email</span>` ; `media/com_breezingformsng/js/site/quickmode-tooltip-init.js` instancie `bootstrap.Tooltip` sur un `<span>` sans `tabindex` ; l'icône est à l'intérieur du label (`&nbsp;` sans `aria-hidden`).
- **Conséquences** : une consigne importante comme la finalité du consentement RGPD n'est lisible qu'au survol, donc invisible au clavier et sur mobile ; le contenu n'est pas relié au champ par `aria-describedby`.
- **Recommandation** : afficher l'aide en texte visible sous le champ (`<div id="… " class="form-text">`) relié par `aria-describedby`, ou à défaut un `<button type="button">` focalisable. Marquer l'icône `aria-hidden="true"`.
- **Effort** : M
- **Risque de régression** : moyen (rendu des formulaires existants)
- **Tests nécessaires** : e2e clavier ; capture mobile.

### UX-012 — Sections sans `<fieldset>` et groupes radio/cases sans nom de groupe
- **Catégorie** : accessibilité front (WCAG 1.3.1, 4.1.2)
- **Impact** : moyen
- **Confiance** : observé (HTML)
- **Preuves** : `<div id="Section_details"><legend>Your details</legend>` : `<legend>` sans `<fieldset>` parent (`<fieldset` : 0 occurrence, `<legend` : 2). Groupe radio « Reason for contact » : `<label for="ff_elem7420">` ne désigne que la première case ; pas de `role="radiogroup"` ni de `<fieldset>`.
- **Conséquences** : un `<legend>` hors fieldset est invalide ; un lecteur d'écran n'annonce pas la question en lisant « Feedback » ou « Support ».
- **Recommandation** : émettre `<fieldset>` + `<legend>` pour sections et groupes de choix (la mise en forme de `legend` dans `theme-carte.css:152` est déjà prête).
- **Effort** : M
- **Risque de régression** : moyen (CSS des thèmes existants, sélecteurs `.nonform-control`)
- **Tests nécessaires** : validation HTML ; axe ; capture des quatre thèmes.

### UX-013 — Champs `type="text"` pour l'e-mail et aucun `autocomplete`
- **Catégorie** : ergonomie/accessibilité (WCAG 1.3.5)
- **Impact** : faible à moyen
- **Confiance** : observé
- **Preuves** : `<input … type="text" name="ff_nm_Email[]" …>` (`type="email"` : 0 occurrence ; `autocomplete` : 1, celui du captcha) ; le téléphone est bien `type="tel"`.
- **Conséquences** : pas de clavier adapté sur mobile, pas de remplissage automatique du nom, de l'e-mail ou du téléphone.
- **Recommandation** : exposer une option « type de champ de saisie » avec `email`, `tel`, `url`, `number`, et un attribut `autocomplete` (`given-name`, `family-name`, `email`, `tel`).
- **Effort** : M
- **Risque de régression** : faible (opt-in)
- **Tests nécessaires** : rendu et validation côté serveur inchangés.

### UX-014 — Bouton « Réinitialiser » proche de « Envoyer », sans confirmation
- **Catégorie** : prévention des erreurs (WCAG 3.3.4)
- **Impact** : faible à moyen
- **Confiance** : observé (HTML) ; comportement du reset déduit
- **Preuves** : `<button class="bfCancelButton btn btn-secondary float-end button" type="submit" onclick="ff_resetForm(this,'click');">Reset</button>` juxtaposé au bouton d'envoi, dans un conteneur `d-flex gap-2` mais avec `float-end` redondant ; l'envoi lui-même est `type="button"` avec `onclick` en ligne.
- **Conséquences** : un formulaire long peut être effacé par un clic involontaire ; le bouton « Reset » est de type `submit` (comportement ambigu).
- **Recommandation** : ne pas afficher « Réinitialiser » par défaut ou demander une confirmation ; utiliser `type="reset"` ou `type="button"` explicite ; supprimer `float-end`.
- **Effort** : S
- **Risque de régression** : faible
- **Tests nécessaires** : e2e envoi/réinitialisation.

### UX-015 — Jeton « texte atténué » de repli sous 4,5:1
- **Catégorie** : contraste (WCAG 1.4.3)
- **Impact** : faible (valeur de repli seulement)
- **Confiance** : ratio calculé sur le CSS ; usage réel non observé
- **Preuves** : `bfng-tokens.css:29` `--bfng-text-muted: var(--bs-secondary-color, #7b8794)` : `#7b8794` donne 3,66:1 sur `#fff` et 3,38:1 sur `#f4f6f8` (la charte annonce 4,5:1). Le jeton sombre `#8892a0` passe (4,7 à 5,2:1).
- **Conséquences** : avec Atum, `--bs-secondary-color` est défini et masque le repli ; le défaut n'apparaît qu'avec un gabarit admin tiers.
- **Recommandation** : remplacer le repli par une valeur plus sombre, par exemple `#5f6b7a` (environ 5,4:1).
- **Effort** : S
- **Risque de régression** : faible
- **Tests nécessaires** : contrôle de contraste des jetons dans la CI.

## 4. Points forts

- **Gestion d'erreurs front exemplaire** (`js/site/quickmode-error-alerts-bootstrap.js`) : `aria-invalid`, `aria-describedby` vers un `invalid-feedback`, résumé `role="alert" aria-live="assertive"` avec liens vers les champs, déplacement du focus et du défilement, changement de page automatique. Le message de confirmation utilise `role="status"`.
- **Thème « carte »** : étiquettes liées par `for`/`id`, hiérarchie claire, focus visible (contour 2 px), mode sombre défini par jetons (`theme-carte.css:44`, `:62`), mise en page mobile propre (capture 390 px : une colonne, pastilles de choix qui s'enroulent, aucun débordement visible).
- **Menu de types de champ** (`quickmode-type-menu.js`) : `combobox`/`listbox`, clavier complet, recherche par saisie, conforme à la charte.
- **Système de jetons** (`bfng-tokens.css`) : héritage des variables Bootstrap/Atum, mode sombre par redéfinition des jetons, zéro `!important`, focus ring défini, `prefers-reduced-motion` géré dans `bfng-widgets.css`.
- **Listes admin** : patron Joomla natif (`searchtools`, `grid.checkall`, tri, légende masquée pour les scripts, états `visually-hidden`).
- **Onglets de l'éditeur** : `role="tablist"`, `aria-controls`, `aria-selected`, `aria-labelledby` corrects.
- **Retour d'état à l'enregistrement** : badge de modifications non enregistrées et bouton d'envoi avec `aria-busy` pendant l'envoi.
- **Widgets** (téléphone international, pastilles) cohérents visuellement avec le reste du formulaire.

## 5. Domaines sans constat significatif

- Navigation générale du front et en-têtes (appartiennent au gabarit du site, hors périmètre).
