BreezingForms by Crosstec has not been maintained since 2022 and does not run on Joomla 6. BreezingForms NG is its community continuation, rebuilt for Joomla 6 and PHP 8.3+. It installs over your existing BreezingForms component and keeps your forms, submissions, scripts and pieces.

What is kept

  • Forms built with QuickMode, with their elements, themes, emails and payment settings.
  • All submissions (records), scripts, pieces and integrator rules: they stay in the same #__facileforms_* database tables.
  • Menu items, permissions and the component configuration, migrated automatically.
  • Stored URLs and code that point to option=com_breezingforms, rewritten to the new component.
  • Custom PHP code that uses the legacy BF* classes, thanks to the bfcompat system plugin.

What changes

  • Only QuickMode remains: forms built in Easy Mode or Classic Mode must be rebuilt in QuickMode.
  • The mobile renderer is gone: use the Bootstrap 5 or one-page layout, which are responsive.
  • Custom code calling old Joomla APIs (JFactory, JRequest, getQuery(true)…) must be updated for Joomla 6.
  • Custom submit code must send the Joomla form token.

Step by step

  1. Back up the site files and the database, and work on a copy of the site first.
  2. List your Easy Mode and Classic Mode forms: they will have to be rebuilt.
  3. Do not uninstall the old BreezingForms component: the NG installer needs its extension entry to migrate it, and uninstalling may remove its data.
  4. Upgrade Joomla to version 6 (PHP 8.3 or later). The old component may stop working at this point: keep the site offline until step 5.
  5. Download the latest BreezingForms NG release and install it with System → Install → Extensions, over the existing component.
  6. Check that the BreezingForms NG - Compatibility system plugin is enabled if your forms contain custom PHP code.
  7. Test each form: captcha, file uploads, emails, payments in sandbox mode, and record exports.
  8. Turn on Joomla debug and look for Class … not found errors in administrator/logs/everything.php: they point to custom code that still calls a removed API.

Need help?

Open an issue on GitHub. Developers can read the technical migration notes, with the Joomla 6 replacements for legacy APIs.
